## 5. State Visuals

### 5.1 Submission Status Badges

```
Pending:    ○ Clock icon    gray border, gray text
Executing:  ◌ Loader spin   blue tint, blue text
Executed:   ✓ CheckCircle   teal/green tint, teal text
Error:      ✕ AlertCircle   red tint, red text
Pre-eval'd: ✨ Sparkles      blue tint, blue text
Graded:     ★ Star           teal filled bg, white text
```

### 5.2 Cell Marker Badges

```
Same approach:       ✓ (blue badge, → blue bg)   — rare, only when matching
Different approach:  ◇ (gray badge, → gray bg)   — default for most cells
Questionable:        ⚠ AlertTriangle (amber)     — suboptimal/incorrect
Error:               ✕ AlertCircle (red)          — execution failure
```

### 5.3 Processing Overlay

- Dimmed background (semi-transparent `--background` + `--border` overlay)
- Centered white card with spinner SVG
- Progress bar (accent color fill on gray track)
- Per-item status list with icons (spinner, check, circle)
- No close button — processing is uninterruptible

### 5.4 Loading States (Skeleton)

- Dashboard: skeleton assignment selector + skeleton filter bar + 4 skeleton table rows
- Per-submission: skeleton 2-column layout with cell-shaped and category-shaped blocks
- All skeletons: `--skeleton` background with `pulse` animation (opacity 0.4 → 0.8)

### 5.5 Error State

- Centered card (max-width 480px)
- `AlertTriangle` icon in `--destructive` color
- Title: "Something went wrong" (18px semibold)
- Description: contextual error message (14px `--muted-foreground`)
- [Try again] button (accent style) + [Go to Dashboard] link (secondary)

### 5.6 Empty State (Dashboard)

- Full centered upload zone with dashed border
- `CloudUpload` icon large
- "Drop .ipynb files here to get started"
- Hint about supported file types
- Appears when no submissions exist for the selected assignment

## 6. Responsive Rules

| Breakpoint | Dashboard | Per-Submission |
|-----------|-----------|----------------|
| **≥1440px** | Full layout. Table columns all visible. | Two panels side-by-side. Right panel at 34%. |
| **1024–1439px** | Same as above. Slightly tighter spacing. | Same as above. Right panel min 300px. |
| **768–1023px** | Search/filter stack. Semester filter on same row as status. | Right panel at 30%, min 280px. Smaller text. |
| **<768px** | Single column. Filters in expandable section. Table horizontally scrollable. | **Mobile mode:** Tabs (Cells / Rubric / Grade) in sticky bar below header. Single column content per tab. |

**Mobile per-submission specifics:**
- Header: compact (same 56px height but smaller breadcrumb font, hidden export/save behind overflow menu)
- Student header: smaller student ID (14px), action buttons in horizontal scrollable row
- Tab bar: 3 pills (Cells, Rubric, Grade) evenly distributed, sticky below header
- Cells tab: full-width cells, code blocks with horizontal scroll
- Rubric tab: categories collapsed by default
- Grade tab: full-width sliders, compact grade summary

## 7. Dark Mode

All components support `.dark` class toggle. No dark-specific visual decisions beyond token inversion:

| Light token → | Dark equivalent |
|--------------|----------------|
| `--bg: oklch(1 0 0)` | `oklch(0.148 0.004 228.8)` |
| `--fg: oklch(0.148 0.004 228.8)` | `oklch(0.987 0.002 197.1)` |
| `--border: oklch(0.925 0.005 214.3)` | `oklch(1 0 0 / 10%)` |
| `--card: oklch(1 0 0)` | `oklch(0.218 0.008 223.9)` |
| `--skeleton: oklch(0.963 0.002 197.1)` | `oklch(0.275 0.011 216.9)` |

- Skeleton pulse animation works in both modes (same CSS, different base color)
- Processing overlay uses semi-transparent dark background in dark mode
- Code block backgrounds stay dark in both modes (dark code on dark bg subtle — use slightly lighter dark for code bg in dark mode)

## 8. Navigation & Header Behavior

### 8.1 Route Structure

```
/submissions/              → Dashboard (list submissions)
/submissions/[id]/        → Per-submission review page
/settings/                → Settings (shared — unchanged from current app)
```

### 8.2 Header States

| Route | Left | Actions | Back |
|-------|------|---------|------|
| `/submissions/` | "SciPro Review / Submissions" | Settings icon | No |
| `/submissions/[id]/` | "← SciPro Review / Submissions / Submission: {studentId}" | [Export YAML] [Save Grade] Settings icon | Yes — goes to `/submissions/` |

### 8.3 Breadcrumb Navigation

- "Submissions" in the per-submission breadcrumb is a clickable link back to `/submissions/`
- Back arrow (ChevronLeft) also navigates to `/submissions/`
- On dashboard, "Submissions" is static text (no link needed)
